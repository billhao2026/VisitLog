第 01 章系统定位：为什么做这套系统

客户已经是合作客户，经营的痛点不在「找客户」，而在「守住并深化关系」——每次通话里的承诺要兑现、暴露的问题要处置、潜在的机会要抓住。拜访志就是为这个场景而生的一套轻量私有系统。

📌我们试过现成工具，但都不对口

🤖 公司大模型（客户画像系统）——会「听」，不会「做」

公司大模型擅长通过录音分析做内容汇总与叠加、记录采购特征、生成客户画像，是强大的分析大脑。但它不是 CRM，分析完就结束了：

  • 没有待办事项——提炼出的行动建议落不了地
  • 没有跟进闭环——谁在推进、推进到哪一步，无从知晓
  • 没有预警机制——敏感问题沉在录音库里没人捞

📋 传统 CRM——会「记档案」，不管「经营关系」

传统 CRM 以客户档案与商机漏斗为核心，服务的是成交前的销售过程。而我们的客户均为已合作客户，档案早就有了，真正要管的是成交之后：

  • 长期合作关系的维护与深化
  • 复购的提升、不同产品线与项目上的合作拓展（授权、试用样品、解决方案）
  • 对接、沟通、交流问题的及时解决

💡 拜访志的定位：补上「从分析到行动」的最后一环

拜访志不做客户画像（那是公司大模型的专长），也不做客户档案库（客户已建档）；它专注三件事：

① 及时跟进客户 —— 通话中的每一条承诺、每一个问题，自动变成待办，逾期即警；
② 提炼问题并妥善处置 —— AI 从通话中提炼问题分类、沉淀要点，敏感问题（故障/投诉/账期/回款）即时预警；
③ 建立与客户的反馈机制 —— 跟进留痕、进展可视、成果反哺，形成「通话 → 行动 → 反馈 → 沉淀」的完整闭环。

🎯两大核心模块详解

⭐ 待办事项——让每个承诺都有下文

待办不只是清单，而是一套承诺管理机制：

  • 自动生成：AI 分析通话时自动提取行动项（如「9/12 前反馈工厂排查结论」），带期限与优先级，避免口头承诺无记录
  • 多维筛选：全部未完成 / 超期 / 今天到期 / 本周内 / 高优先 / 已完成，概览页数字块点击直达对应筛选
  • 跟进留痕：每条待办可记跟进（推进中/有突破/已闭环），写下「做到哪一步、还有什么堵点」，替代只改日期的形式主义
  • 超期即警：过期待办自动标红，概览页「已超期」数字块红色高亮，一眼看到失约的承诺

⭐ 重要事项预警——敏感问题绝不沉底

系统对通话内容做敏感信号扫描，命中即进入预警池：

  • 预警范围：故障、投诉、账期、回款等敏感关键词
  • 首页横幅：概览页顶部横幅显示待处理预警数，点击直达处理页
  • 逐条处置：每条预警可标记处理方式与结论，处理完毕自动闭环，全程留痕
  • 实战价值：某客户提及「半年返修 2-3 回、次品率偏高」，另一客户同期反馈同类故障——两条预警对照，快速识别跨客户的批量质量问题，及时反馈工厂排查

🔁闭环工作流：从一通电话到问题解决

📞 上传录音→ 🎙 自动转写→ 🧠 AI 分析提炼→ ⭐ 待办生成+ ⭐ 敏感预警→ ✍ 跟进留痕→ ✔ 闭环处置→ 📚 字典反哺（越用越准）

整个链路里，待办与预警是两大枢纽：待办确保「答应客户的事有着落」，预警确保「客户不满的事有人管」。字典反哺则让系统随使用不断进化——你每修正一次归类，下次同类内容就自动判对。

第 03 章操作手册 · 从启动到日常使用

🚀快速上手（三步开始）

1

启动服务

双击项目目录下的 启动拜访志.bat；或命令行执行 node server\server.js。服务在本机 8897 端口运行，窗口显示访问地址即启动成功，保持窗口开启即可。

2

打开页面

电脑访问 http://localhost:8897/；手机（同一 WiFi）访问 http://192.168.16.240:8897/（以启动窗口打印的 IP 为准）。建议在手机浏览器中「添加到主屏幕」，一键直达。

3

上传第一通录音

点击右上角上传录音按钮，选择音频文件即完成。系统自动排队转写→AI 分析，按钮上会实时显示「转写中 · 余 N」「待分析 N」状态，全程无需等待或手动刷新——分析完成，页面自动更新。

💡 手机上传最顺手：通话结束后，用微信/文件管理器把录音发送或保存到手机，再在手机浏览器打开本系统上传——从挂电话到完成沉淀，一分钟内搞定。若手机提示页面样式异常，多为浏览器缓存了旧版，在地址后加 ?r=2 强制刷新即可。

⏱️日常五分钟工作流（建议每天固定执行）

把系统用出价值的关键，是养成一个极轻量的日常节奏。以下流程实测五分钟内完成：

1

看概览：今天该管什么（约 1 分钟）

打开概览页，三处必看：顶部预警横幅（有红色横幅立即点进去处理）；统计卡「已超期」（红色数字 = 昨天失约的承诺）；重点事项主线（置顶的五星要点，客户的核心诉求主线）。

概览页每个数字块都可以点击，直达对应筛选列表

2

清预警：敏感问题不过夜（约 1 分钟）

预警页按严重程度列出故障/投诉/账期/回款等敏感信号。逐条打开，判断真伪与优先级：误报直接标记排除；属实标记处理方式、写明结论，转成待办或直接闭环。

3

推进待办：清「今天到期」与「超期」（约 2 分钟）

待办页切到「今天到期」+「超期」两个筛选，逐条处理：能办的当场办，办不了的记一条跟进（写清推进到哪一步、堵点是什么），必要时顺延日期并说明原因。高优先（⭐）项永远先处理。

4

随手传：当天的电话录音丢进队列（约 30 秒）

把今天与客户的通话录音上传，剩下的交给系统。明天打开概览，新的待办和预警已自动就位——这就是系统「越用越懂你」的节奏。

⚠️ 一个原则：待办可以顺延，但每条超期待办必须留下跟进记录。「顺延 + 写明原因」是管理动作，「只改日期不说明」是自欺——系统用超期红色高亮提醒这一点。

📖七大页面逐一说明

系统顶部共七个页签：概览 · 通话 · 待办 · 重点 · 预警 · 客户 · 字典。页签上会显示未完成待办数、待处理预警数徽标，点击切换页面。

🏠 概览（首页）

每天的工作驾驶舱，全部数字块可点击直达：

  • 四张统计卡：累计通话 / 未完成待办（含高优先数）/ 已超期 / 今日已推进
  • 重点事项主线：置顶五星要点前 6 条，点开即进客户档案
  • 待办节奏：超期/今天到期/本周内/高优先四格数字，点击跳转对应筛选；下方列高优先与今日到期待办
  • 最近跟进动态：谁在什么时间推进了什么

📞 通话

全部通话记录列表，按时间倒序：

  • 显示客户、时长、摘要要点、自动归类结果
  • 点击任意一条进入通话详情：完整转写稿 + AI 提炼的要点/问题/承诺/情绪
  • 详情内可修正归类、编辑要点、补充人工备注

⭐ 待办（核心）

所有行动项的中枢，六大筛选：

  • 全部未完成 / 超期 / 今天到期 / 本周内 / 高优先 / 已完成
  • 每条待办显示来源客户、期限、优先级、生成时间
  • 点开待办 → 写跟进记录（推进中/有突破/已闭环）→ 必要时顺延
  • 筛选状态可通过地址直达，如 #/todos?scope=overdue

📌 重点

跨通话沉淀的客户核心要点：

  • AI 从通话中提炼的长期性重点（采购偏好、合作意向、关键人信息等）
  • 可置顶（五星）、可人工补充修正
  • 概览页「重点事项主线」即取自这里的置顶项

🚨 预警（核心）

敏感信号专属处理台：

  • 故障 / 投诉 / 账期 / 回款等敏感命中，按严重程度排列
  • 每条预警点开可见命中原文上下文
  • 处置四选：误报排除 / 已核实 / 转待办 / 已闭环，均留痕

👤 客户

已合作客户的关系全景页：

  • 汇总该客户全部通话、待办、重点、预警
  • 📤 导出分享 HTML：一键生成离线单文件（含拜访记录/待办/要点/跟进），可直接发微信或邮件给同事/上级——对方无需装任何软件，浏览器打开即看

📚 字典（让系统越用越准）

字典页是系统「自我进化」的引擎，三个区块：

  • 分类体系：通话自动归类的类目树（技术咨询/售后/商务/投诉等）
  • 自动归类规则：当前生效的关键词→类目映射，识别率一目了然
  • 术语纠错：顶部输入行填「误 → 正」即可添加；也可点击扫描一键扫描全库转写稿，把行业黑话（型号俗称、方言人名等）批量纠正——改一处，全库生效，下次转写直接输出正确词

💎三大独特优势

优势一：从「分析」到「行动」的闭环——大模型与 CRM 都缺的那一环

公司大模型擅长听懂电话（画像、汇总、特征），传统 CRM 擅长存住档案（基本信息、商机阶段），但「听懂之后该做什么、谁在什么时候做、做了没有」——这一段恰恰是客户关系出问题的高发区。

本系统把这一环完整接住：AI 分析 → 待办自动生成 → 预警拦截 → 跟进留痕 → 闭环复盘。答应客户「9/12 前反馈工厂排查结论」，系统就真的会在 9/12 提醒你；客户随口抱怨「次品率偏高」，系统就真的会把它拦进预警池而不是沉进 200 条通话记录里。

优势二：为「已合作客户」定制的轻量——不重复建档，只经营关系

传统 CRM 的重头戏是「客户档案管理」——但对全是已合作客户的团队，重复维护档案是纯负担。本系统零档案门槛：上传第一通电话，客户页签自动生成，之后每通电话自动归档到对应客户名下。

省下的精力聚焦在真正产出复购的动作上：跨产品线机会识别（客户提到竞品痛点即成待办）、解决方案跟进（授权、试用样品的发出与回收全程留痕）、长期关系维护（重点事项置顶，核心诉求不随时间遗忘）。

优势三：越用越准的私有大脑——数据不出门，经验不出走

网上录音工具按条收费且转写稿存在第三方云端，客户数据安全存疑；本系统数据全本机（SQLite + 本地音频），零持续费用。更重要的是字典反哺机制：你修正的每一个术语、每一处归类，都成为系统的私有知识——三个月后，它对你们行业黑话、客户简称、产品型号的识别精度，是任何通用工具不可能达到的。

这套「纠错 → 全库生效 → 下次直接判对」的进化能力，等于团队把通话处理经验沉淀成了可传承的数字资产——新人接手客户，历史通话、待办、重点、字典全部现成。

📌 与公司大模型的配合关系（不是替代，是接力）：本系统负责「行动层」——待办、预警、跟进、闭环；公司大模型负责「分析层」——客户画像、采购特征、录音内容汇总叠加。两层各司其职：本系统的转写稿与客户沉淀，可作为大模型画像分析的输入；大模型的全景画像，反过来辅助本系统判断哪个客户的待办更值得优先推进。

第 05 章未来规划 · 从内部工具到开源共享

🌍为什么值得开放给更多人

这套系统解决的不是某个团队的特例问题，而是一个普遍存在却被长期忽视的行业痛点：

  • 中小销售团队的普遍困境：请不起 CRM 实施顾问，也用不惯为大企业设计的重型系统；客户电话打完就忘，承诺没人盯，问题沉底没人捞。
  • 外勤/驻场/售后场景的空白：大量行业（设备制造、工程服务、医药流通、政企服务、专业服务）的核心工作都发生在电话里，而现有工具几乎没有为「通话→行动闭环」设计。
  • 数据主权的现实需求：越来越多的团队意识到客户通话数据是最敏感的资产之一，「存第三方云端按条付费」的模式天然让人不放心。

「上传一通电话 → 自动知道该做什么 → 做完有据可查」——这个闭环对任何靠客户关系吃饭的团队都成立。这是本系统通用价值的根基。

❤️帮助他人的意义

对销售个人

不再靠脑子和笔记本记承诺。每一通电话的价值被完整保留，每一句「回头我给您确认一下」都有下文。新人三个月上手变成六周——历史通话、待办、重点全部现成，客户交接不再断层。

对小团队管理者

不装监控式软件，也能看到团队真实的工作节奏：谁在推进、谁在积压、哪些客户的问题长期没解决——从「口头汇报」到「数据说话」，且数据全在本机，团队信任零损耗。

对客户

这是最终极的意义：供应商不再忘记答应过的事，不再对反复提出的问题装聋。每一次被预警拦下的投诉、每一个被闭环的承诺，都是客户体验的一次真实改善——工具的价值，最终落在关系里。

对开源社区

提供一个「AI 落地线下业务」的完整参考：本地语音转写 + LLM 分析 + 领域字典反哺的完整链路，全部用轻量技术栈实现。任何人都可以基于它改造出自己行业的版本。

🌱 一句话总结：把「听过的电话」变成「做过的事」，把「答应的话」变成「兑现的承诺」——这套系统想帮每一个靠客户信任吃饭的团队，把信任经营成体系。
